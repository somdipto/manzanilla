===================================================

credentials, real speech, physical tablet or acoustic capture. The ASR,
translation and synthesis providers are deterministic in-process fakes. This
checks actual LiveKit room/media/data transport and the worker's event ordering,
not speech recognition, echo cancellation, voice quality or human latency.

Both arms used the identical synthetic PCM, server and probe. A device sends
audio while a fake greeting is still playing. The fake ASR sends the documented
auto-mode user_turn_taken event, followed by a synthetic committed utterance.
The old worker used speech_start to interrupt, whereas the candidate uses
user_turn_taken. This tests both opening-mic ordering and the event correction;
it does not establish how the real ASR recognizes a guest amid speaker echo.

Baseline: FAIL — worker did not receive microphone audio during greeting.
Candidate: PASS — 42 decoded microphone frames reached the worker; the device
received agent audio; interruption cleared the local playback queue; the device
received the matching synthetic original/translation caption. One measured
worker event-to-local-queue-clear interval was 0.07 ms. This is a local event
ordering observation, NOT guest-audible interruption latency or a percentile.

Separate token/deletion observations on the same disposable server:
- DeleteRoom with only roomAdmin returned 401; roomCreate is required.
- Deleting a room never created returned 404/not_found.
- Deleting an existing room returned 200; another client then joined using the
  exact same still-valid token, recreating that room.
- A 2-second initial token stayed connected after 4 seconds. Following a server
  restart, the same Python SDK reported reconnecting then reconnected. A fresh
  connection with the nominally expired original token was also accepted soon
  afterwards. The server's expiry tolerance was not measured. This is not an
  Android reconnect test or proof of immediate token revocation.

Historical live-provider figures in PR #9 were 3.74s and 5.74s from synthetic
input-end mark to first Fish audio-chunk mark, for one Spanish-to-English
utterance using the NVIDIA gpt-oss-20b stand-in. No paired old-route baseline or
physical acoustic comparison was recorded. The prior marker preceded the worker
capture_frame attempt; it was not an audible speaker boundary. These two values
cannot establish that the route beats the old route or meets a p95 target.
Source: https://github.com/somdipto/manzanilla/pull/9

The live-provider probe now scopes appended timing records to the exact room,
waits for local input SDK playout, and labels its worker capture-frame attempt
honestly. Its SDK recording includes the greeting and possible silence; it does
not establish audible translation, correctness or naturalness. The old and new
timing boundaries differ, so historical numbers are not directly comparable.
