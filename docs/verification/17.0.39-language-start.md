# 17.0.39 translation startup and language placement

Candidate based on main e2579c0 (17.0.38), version 17.0.39 / code 69.

An uncertain `und` caption previously inherited the last known speaker's side.
It now stays neutral, including after a known guest or receptionist utterance.
The selected language codes alone determine left/right placement. Repeated
utterances and X/Y/Y/X/X sequences keep their own source language. Uncertain
whitespace translations are normalized to empty, preserving original Unicode.

Direct Fish setup prepares immutable agent configuration on the language screen,
debounced by 350 ms and serialized with Start. It opens no session or media.
Leaving the app cancels preparation and its HTTP calls. Configurations are cached
by credential/configuration hash rather than retaining only the last language.
The first greeting is disabled. The session prompt explicitly limits both source
and destination to the selected pair and preserves the transcribed original.
Fish configuration revision 17 avoids reusing previously published agents.

Fish's documented `strict_language` setting accepts one speaking language only;
it cannot restrict a bilingual interpreter to two languages. Multilingual ASR
remains enabled, with Nova-3 only for pairs in its documented switching set and
Scribe for other pairs. A model prompt cannot recover words already mistranscribed
by ASR. These changes do not establish recognition accuracy for accents or short
phrases, or a measured phone startup/speech latency improvement.

Local isolated verification:

- 411 Python tests passed; two existing dependency deprecation warnings.
- 143 JVM tests passed; no failures, errors or skips.
- Node language ledger tests cover all 2,652 ordered picker pairs.
- All five Chromium154 browser scenarios passed using the shipped assets.
- Debug lint, APK and instrumentation APK assembly passed. Local builds used the
  existing pinned-source AudioSwitch substitution documented in README.md;
  GitHub CI resolves the normal artifact.
- Native intercepted-HTTP tests now cover preparation without session/audio,
  Start issuing only session creation after preparation, reuse after language
  changes, and cancellation before dispatch. Emulator execution is a CI gate.

The one-time PR provider check creates only a uniquely named synthetic tool,
agent and session, sends seven synthetic text turns, then ends/removes its owned
resources. It uses the actual Kotlin-generated configuration. It does not publish
microphone audio and is not acoustic evidence. Provider session history persists.
Its result and signed update delivery must be checked separately before release
claims. Existing package/signing identity, credential injection and update flow
are preserved; the authorized testing key remains supplied by Actions.
